# Iris Flower Multi-Class Classification with Machine Learning and Interactive Dashboard

Predict the species of an iris flower (**Setosa**, **Versicolor**, **Virginica**) from four measurements,
compare **Logistic Regression** with a **Decision Tree**, and explore everything in a **Streamlit dashboard**.

## 1. Quick start

```bash
pip install -r requirements.txt     # 1. install libraries
python train_model.py               # 2. (optional) train, validate and save the models
streamlit run app.py                # 3. open the dashboard (http://localhost:8501)
```

Step 2 is optional: if `models/` is empty or unusable, the dashboard trains and saves the models by itself the
first time it starts. Saved models are loaded from disk afterwards, so nothing is retrained on every start.

Other things you can run:

| Command | What it does |
|---|---|
| `jupyter notebook notebooks/Iris_Classification_Pipeline.ipynb` | The step-by-step teaching notebook (EDA, models, graphs). Also runs in Google Colab: upload the `.ipynb` and choose Runtime > Run all. |
| `python -m pytest tests -q` | 57 automated tests (`pip install pytest` first). |

## 3. What was reviewed and changed in the existing project

The existing project (one notebook, `requirements.txt`, `README.md`, `results/`) was inspected first and **kept**.

**Findings from the review**
- **No data leakage:** `StandardScaler` was already inside the `Pipeline`, so it learns from training data only.
  A test now proves it (the scaler's mean equals the training-set mean, not the full-data mean).
- **No incorrect evaluation:** metrics use macro averaging on a stratified 80/20 split; cross-validation re-fits the
  whole pipeline per fold. The one duplicated flower in the Iris data lands in the training set only (with
  `random_state=42`), so no identical flower appears in both train and test.
- **Duplicate logic:** the split, pipelines and metrics existed only inside the notebook, so a dashboard would have
  needed a second copy. They now live once in `src/` and are used by `train_model.py` and `app.py`. The notebook is
  intentionally left self-contained so it still runs alone in Colab; a check confirms its metrics equal those of the
  saved models.

**Changes to the notebook:** the results folder now works from `notebooks/` (and from Colab); the
cross-validation table has the same columns as `train_model.py`; a data-quality note about the duplicate row was added.
All results and graphs were regenerated by re-running it (no errors).

**Bugs found and fixed while building the dashboard** (both caught by the tests)
1. CSV-injection protection silently skipped text columns because pandas 3 stores text as a new `str` type.
2. The decision-tree drawing crashed because a plain matplotlib figure had no rendering canvas.

**Visual problems found by opening the running dashboard in a real browser (Chromium) and fixed**
(the automated tests could not see these, because the pages ran without errors)
3. *Home:* the "Best model" card showed **"Decision T..."** (cut off). Its font is now smaller so "Logistic Regression" fits too.
4. *Model Comparison:* the results table was squeezed into a narrow column and the **Recall and F1 columns were hidden**.
   The table is now full width, with the bar chart below it.
5. *Sidebar:* the training time read `...+00:00 UTC`; the redundant offset is removed.
6. *Phones:* the sidebar opened on top of the page. It now starts collapsed on small screens (`initial_sidebar_state="auto"`).
7. *Flower Prediction:* the Decision Tree often shows exactly 100% confidence, which looks like certainty. A short note now
   explains that a tree's probability is the share of training flowers in its final box (leaf).
8. The developer-only "Deploy" button is hidden (`toolbarMode = "minimal"`) for a cleaner demo.

Three regression tests were added for 3, 4, 5 and 7.

## 4. The dashboard

| Page | What you can do |
|---|---|
| **Home Dashboard** | Dataset overview (150 samples, 4 features, 3 classes), KPI cards, best model (chosen from measured results), charts, navigation buttons. |
| **Dataset Explorer** | Table with species and range filters, dimensions, feature names, class distribution, missing values, duplicate records, histograms/box plots, correlation heatmap, interactive pairplot (scatter matrix). |
| **Model Comparison** | Results table, interactive bar chart, confusion-matrix heatmaps for both models, 5-fold cross-validation, per-species report. |
| **Flower Prediction** | Enter four measurements, press **Predict**, see the species, class probabilities, a plain-language explanation and where the flower sits among the dataset. Invalid values give clear errors; unusual values give warnings. |
| **Batch Prediction** | Upload a CSV, see per-row validation, predictions in a table, and download the original data + predictions. A sample template is provided. |
| **Model Insights** | Decision Tree feature importance, the tree drawn and written as rules in cm, decision boundary (two chosen features **or** PCA) with its limitations, misclassified test flowers. |

**CSV rules (Batch Prediction):** required columns `sepal_length, sepal_width, petal_length, petal_width`
(headers such as `Sepal Length (cm)` are also accepted); numbers between 0.1 and 15 cm; up to 10,000 rows and 5 MB.
Invalid rows are not predicted; they stay in the output with the reason in a `status` column. Your own columns are
never overwritten. Text cells starting with `=`, `+`, `-` or `@` get a leading apostrophe in the downloaded file so
spreadsheet programs do not run them as formulas.

## 5. How models are trained, saved and loaded

1. 80/20 stratified split, `random_state=42` (120 train / 30 test, 10 test flowers per species).
2. Each model is a Scikit-learn `Pipeline`: `StandardScaler` then the classifier, fitted on **training data only**.
   (The Decision Tree does not need scaling; it uses the same pipeline for a fair comparison. It has `max_depth=3`.)
3. **Validation gate:** the pipeline must be fitted, give valid predictions and probabilities, finite metrics, and a
   test accuracy of at least 0.80. If anything fails, **nothing is saved** and previously saved models stay untouched.
4. Passing models are written with `joblib` (the file contains the fitted scaler **and** the model) to a temporary
   folder and then moved into `models/`; `model_metadata.json` records checksums, metrics, the scikit-learn version
   and a fingerprint of the dataset.
5. When loading, the app checks the files, checksums, scikit-learn version, split settings and data fingerprint.
   If any check fails it explains why and trains fresh models instead of using stale ones.

Only open `.joblib` files you created yourself: loading a joblib file runs code, like any pickle file.

## 6. Results (produced by running `train_model.py`; test set = 30 flowers)

| Model | Accuracy | Precision (macro) | Recall (macro) | F1 (macro) | 5-fold CV accuracy |
|---|---|---|---|---|---|
| Logistic Regression | 0.9333 | 0.9333 | 0.9333 | 0.9333 | 0.9533 (std 0.0452) |
| Decision Tree (max_depth=3) | 0.9667 | 0.9697 | 0.9667 | 0.9666 | 0.9600 (std 0.0249) |

- The Decision Tree scores higher on this test split (1 mistake vs 2: Logistic Regression confused one Versicolor
  with Virginica and one Virginica with Versicolor; the tree confused one Versicolor with Virginica).
- **Be careful with this conclusion:** with 30 test flowers, one flower is 3.3 percentage points. The cross-validated
  gap (0.953 vs 0.960) is smaller than the fold-to-fold variation, so the models perform about equally well.
- Decision Tree feature importance: petal length 0.579, petal width 0.421, both sepal features 0.
- The dashboard picks the best model from these measured numbers each time (highest macro F1, ties broken by accuracy,
  and a tie is reported as a tie); no value is hard-coded.

Files in `results/`: 12 graphs (`01`-`10`, from the notebook), `model_comparison.csv`, `cross_validation_results.csv`,
`metrics.json`, `classification_report_*.csv`, `misclassified_*.csv`.

## 8. Known limitations

- **Visual checks were done in Chromium only**, using screenshots at 1400 px and 390 px wide. Other browsers, tablet
  sizes and the Model Insights, Dataset Explorer and Batch pages at phone width were not inspected on a phone; please
  open the dashboard once and look through each page before presenting it.
- The Streamlit automated tests and the browser script cover the main paths; they do not prove there are no bugs in
  unusual situations (for example a very large CSV near the 5 MB limit was not tried in the browser).
- The best model is picked by its score on the 30-flower test set (as requested), not by cross-validation. With only two
  models and no tuning this is acceptable, but the dashboard states that the difference is within noise.
- Iris is a tiny, easy dataset (150 flowers). Both models score above 93%, and differences between them are within
  noise. Results should not be generalised to other data.
- The decision-boundary charts come from separate two-input models; they illustrate behaviour but are not the
  boundary of the four-feature model (the page explains this).
- Saved `.joblib` files only work with the scikit-learn version that created them (1.9.1 here). On another version the
  app detects this and retrains automatically.
- Everything was tested on Python 3.13 with the library versions listed in section 7; other Python and library
  versions were not tested.
